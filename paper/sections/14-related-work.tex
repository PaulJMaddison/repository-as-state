\section{Related Work and Narrowed Novelty Boundary}
\label{sec:related}

Hostile literature review materially narrows the novelty claim. Repository-backed agent memory, commit-history memory, sequential software evolution benchmarks, interrupted-task handoff evaluation, lower-cost repository exploration, durable execution, and repository-scale replaceable compute all predate this experiment. RaS is defensible only if it credits those overlaps and focuses on the treatment they do not isolate.

\subsection{Repository-level agents and sequential software evolution}

SWE-bench and SWE-agent establish repository-level issue resolution and agent--computer interfaces \citep{jimenez2024swebench,yang2024sweagent}. OpenHands and its SDK provide sandboxed execution, lifecycle control, memory mechanisms, security features, and multi-model routing \citep{wang2024openhands,wang2025openhandsSDK}. SWE-STEPS already evaluates chains of dependent pull requests and shows that isolated-task evaluation can overstate long-horizon performance \citep{shastry2026swesteps}. RaS therefore cannot claim novelty for repository-level coding or sequential task chains.

Its narrower experimental variable is whether predecessor \emph{reasoning-session history} is needed after each accepted state transition when the same dependent task chain, model, tools, and accepted project state are otherwise matched.

\subsection{The closest empirical challenge: interrupted-task handoff}

Handoff Debt is the closest direct empirical challenge found in this audit \citep{kc2026handoff}. It freezes repository state at deterministic interruption points and compares successor agents receiving repository-only state, raw traces, summaries, or structured notes. Across multiple models, context-bearing handoffs substantially reduce agent events and cumulative prompt tokens relative to repository-only takeover, while solve-rate effects are smaller and model dependent.

That work defeats any broad claim that “the repository alone makes predecessor context unnecessary” or that repository-only reconstruction is automatically economical. The remaining distinction is the reset boundary. Handoff Debt interrupts \emph{partially completed tasks}, where intent and evidence may not yet have been externalised into accepted engineering artefacts. RaS proposes disposal \emph{after validated accepted transitions} and then asks whether the next dependent task can proceed without predecessor reasoning history. P0 must test whether that boundary difference actually matters.

\subsection{Git-bound and repository memory}

Guo explicitly argues that agentic-development memory should be Git-bound, linking assistant sessions to commit state and routing queries over structural maps, episodes, and decision synthesis \citep{guo2026gitmemory}. This is strong overlap with the broad “repository as memory” intuition. However, it makes session history durable inside the Git-bound memory system. RaS instead tests whether predecessor session/transcript state can be absent after an accepted transition.

Other work uses commit history as non-parametric repository memory for code localisation \citep{wang2025repomemory} or builds online repository memory from historical commits to learn project-specific change patterns \citep{li2026learningcommit}. These results make clear that repository history can be useful memory, but they also show that a current snapshot may omit project-specific patterns. RaS therefore treats Git history and semantic artefacts as candidate durable-state carriers rather than claiming source snapshots are sufficient.

\subsection{Repository context files}

Repository instruction files are established context mechanisms. Sun et al. document more than twelve thousand public Cursor rule files containing project context and engineering guidance \citep{sun2026cursorrules}. Gloaguen et al. find that AGENTS.md-style context files can reduce task success and raise inference cost despite increasing exploration \citep{gloaguen2026agentsmd}. Khatri's two-agent ablation finds no measurable correctness effect within declared bounds and highlights agent-specific task difficulty \citep{khatri2026contextfiles}. These findings weaken any assumption that more curated repository documentation automatically improves resumability. Condition C should study marginal continuity value, not assume documentation is beneficial.

\subsection{Repository exploration and tiering}

Repository exploration is itself a measurable, costly stage. Awad and Ivanov evaluate lower-cost explorer models and identify quality/cost operating points for localisation \citep{awad2026exploration}. RouteLLM studies learned model routing \citep{ong2024routellm}. Consequently, separating a high-capability reasoner from cheaper exploration/execution is not a novel RaS contribution; it is a secondary architecture to evaluate separately.

\subsection{Agent memory and context engineering}

MemGPT treats extended interaction as managed virtual context \citep{packer2023memgpt}, while current surveys cover episodic, semantic, reflective, hierarchical, and learned memory \citep{du2026memory,luo2026memory}. Context-engineering guidance explicitly recommends compaction, structured memory, retrieval, and subagent architectures for long-horizon agents \citep{anthropic2025context}. These systems invalidate a straw-man comparison against agents that always replay full history.

RaS asks a different question: after accepted engineering boundaries, can the marginal value of predecessor model-native history become small enough that it is not required for programme continuity?

\subsection{Durable execution, checkpointing, and transaction terminology}

Durable Functions formalises stateful serverless workflows under compute--storage separation and replay \citep{burckhardt2021durable}. Durable AI workflow research also studies semantic isolation across pauses and continuations \citep{mozafari2026semantic}. These are important precedents and terminology constraints. RaS does not claim to invent checkpoint/restart or transactional computation. Its object of reconstruction is semantic engineering state for a fresh nondeterministic reasoner, not deterministic workflow replay.

\subsection{Inference-state management}

PagedAttention/vLLM demonstrates that KV-cache allocation and sharing affect LLM-serving throughput \citep{kwon2023vllm}. DistServe separates prefill and decode resources \citep{zhong2024distserve}; Mooncake builds a KV-cache-centric disaggregated serving architecture \citep{qin2024mooncake}. These systems show why simplistic “one conversation equals one GPU allocation” reasoning is wrong. RaS makes no provider-internal saving claim.

\subsection{Repository-state infrastructure}

Cursor Continuity persists a write-ahead log in S3-compatible object storage and materialises repository-serving state on replaceable nodes \citep{marti2026continuity}. This is a repository-infrastructure precedent only. It does not evaluate model continuity, forced reasoning-state reset, or reconstruction economics.

\subsection{What remains plausibly novel}

After removing generous claims, the audit finds a narrower combination not identified in the reviewed prior work:

\begin{enumerate}
    \item disposal of high-capability reasoning-session state specifically at \emph{accepted/validated sequential engineering boundaries};
    \item a matched A/B intervention intended to hold repository state, dependent task, model capability/configuration, tools, and environment constant while varying predecessor reasoning history;
    \item reconstruction-cost accounting designed so repository-only resumption is explicitly allowed to lose;
    \item an external state-reconstruction probe plus semantic-state ablation at accepted boundaries to identify which durable artefacts carry marginal continuity value.
\end{enumerate}

RRI, tiered execution, Git-backed state, sequential tasks, and repository retrieval are not independently strong novelty claims. The surviving novelty is sufficient to justify a carefully controlled pilot, not to claim a new general theory before evidence.
