\section{Threats to Validity}
\label{sec:threats}

RaS is unusually vulnerable to experimental design choices because the intervention acts on information availability. A convincing result must therefore make alternative explanations difficult.

\subsection{External validity}

\textbf{Single-repository bias} is immediate if early experiments use one system. Language, module structure, test culture, repository age, and engineering conventions can all affect reconstruction. \textbf{Private-subject bias} compounds this problem because independent researchers cannot reproduce the initial subject exactly. Public-repository replications are therefore required before broad claims.

\textbf{Single-model bias} matters because models differ in code navigation, retrieval, context use, tool calling, and tolerance for incomplete documentation. \textbf{Repository size}, \textbf{task locality}, and \textbf{dependency width} may determine whether bounded reconstruction is feasible. A method that works for a local patch may fail for cross-service migrations. Results in coding must not be silently generalised to personal assistants, embodied agents, or other domains.

\subsection{Internal validity}

\textbf{Task selection} can make either condition look favourable. Tasks naturally encoded in tests may favour RaS; tasks dependent on undocumented conversation may favour persistence. Selection rules must be fixed before outcomes.

\textbf{Historical commit survivor bias} occurs when tasks are reconstructed from successful historical changes, excluding realistic dead ends and abandoned work. \textbf{Future-history leakage} is especially serious because a later commit, tag, reflog, packfile, branch, comment, or test can reveal the solution to a historical task. Isolation must be fail-closed.

\textbf{Human intervention} can become an undeclared continuity channel. Hints, manual repair, prompt rewriting after failure, or transferring conclusions across conditions invalidate the reset intervention. \textbf{Order effects} can arise if operators or infrastructure learn the task corpus. \textbf{Contamination} can occur through shared caches, generated artefacts, model pretraining on public solutions, or accidental workspace reuse.

\textbf{Model nondeterminism} means small samples can mistake sampling variance for architecture effects. \textbf{Provider changes} may alter behaviour during a longitudinal study even when a model label appears stable.

\subsection{Construct validity}

RRI measures correct continuation after reset; it does not directly observe the latent action distribution in the repository-sufficiency definition. \textbf{Reconstruction accuracy} is itself measured through a rubric and may overvalue explicit textual state. The state-reconstruction probe must therefore be analysed alongside actual engineering outcomes.

\textbf{Documentation quality} can dominate the treatment. A heavily curated repository may measure the value of disciplined documentation rather than repositories generally. This is scientifically acceptable if reported, but limits generalisation.

\textbf{Ablation design} is difficult because semantic state is redundant. Removing an ADR while leaving a test or comment that encodes the same decision may create a false conclusion that the ADR was irrelevant. Conversely, removing too much can damage buildability and change the task itself.

\textbf{Hidden-verifier validity} matters because a verifier may reward one implementation style, omit business behaviour, or accidentally leak solution structure. Hidden verification should assess behaviour rather than preferred code shape.

\textbf{Reconstruction-cost classification} can bias the economic result. If repository reading required only because history was destroyed is counted as generic reasoning rather than reconstruction, RaS appears artificially cheap. The classification rule must be preregistered.

\textbf{Token telemetry gaps} and \textbf{prompt caching} complicate cost comparison. Providers may expose input/output tokens while hiding internal retrieval, cache storage, or scheduler behaviour. Repeated prefixes may advantage one condition. The study should report observable proxies rather than infer hidden cost.

\subsection{Statistical conclusion validity}

P0 is a pilot and will have limited statistical power. It should validate intervention integrity, telemetry, task construction, and variance rather than support general effect-size claims. Later experiments require predeclared sample sizes, confidence intervals, missing-data rules, randomisation or counterbalancing, and multiplicity treatment.

Failed or aborted runs must not disappear. A preregistered distinction between agent failure and harness/infrastructure failure is required, and excluded runs must remain auditable.

\subsection{Central falsification condition}

The most direct criticism is that RaS simply replaces conversation replay with repository rediscovery. If reconstruction tokens, file reads, searches, model calls, or elapsed time grow enough with repository size and task depth to erase outcome-normalised advantages, the architecture may remain technically resumable while its state-economics hypothesis fails. This possibility is a central falsifier, not a caveat to be minimised.
