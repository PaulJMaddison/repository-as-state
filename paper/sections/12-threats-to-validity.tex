\section{Threats to Validity}
\label{sec:threats}

RaS is unusually vulnerable to validity failures because its treatment is information availability. A convincing study must control not only prompts but every hidden state channel through which predecessor work can survive.

\subsection{Construct validity}

\textbf{Repository sufficiency is conditional, not intrinsic.} Success depends on task class, depth, model, tool contract, environment, and repository quality. The paper therefore operationalises a matched behavioural comparison rather than latent action-distribution equality.

\textbf{RRI is descriptive.} It mixes reconstruction and implementation ability, can be inflated by easy tasks, and is not a causal estimator. Matched A/B outcomes and complete-sequence success remain primary.

\textbf{Reconstruction accuracy} depends on a rubric. Textual similarity can reward verbose reports without engineering understanding. Hidden ground-truth items and blinded scoring are preferable.

\textbf{Reconstruction-cost classification} is manipulable unless frozen. Repository reading, search, and model calls required to rebuild lost context must not be silently moved into a generic reasoning bucket.

\textbf{Economic observability is limited.} Token and call counters are proxies; provider-internal GPU scheduling, KV-cache residency cost, storage amortisation, and margin are not measurable from ordinary client telemetry.

\subsection{Internal validity}

\textbf{Treatment confounding} is the largest pre-P0 risk. A new session can differ from a persistent one in system prompts, provider account memory, prompt caches, tool sessions, executor state, shell history, untracked files, worktrees, environment variables, build artefacts, dependency caches, IDE state, clocks, or network access. Canonical rematerialisation and invariant configuration are mandatory.

\textbf{Future-history leakage} is catastrophic. A historical checkout inside a full clone can retain future solution objects through refs, reflogs, packs, alternates, tags, remotes, or worktree links. The FUTURE_HISTORY_LEAK_GATE must fail closed before the model is invoked.

\textbf{Task leakage} can arise from future commit messages, issue edits, branch names, changelogs, TODOs, generated documentation, future tests, hidden patch files, or CI artefacts. Legitimate cutoff-state information is allowed; post-cutoff solution information is not.

\textbf{Verifier leakage} invalidates behavioural testing if the agent can access hidden tests, expected patch text, verifier output beyond the declared interface, or task-generation ground truth.

\textbf{Human rescue} is an undeclared continuity channel. Hints, file pointers, manual edits, prompt changes after failure, copied conclusions, and selective reruns must be prohibited.

\textbf{Executor differences} can confound continuity if A and B use different editing agents, privileges, tool schemas, or retry behaviour. Tiered execution is therefore outside the primary P0 comparison.

\textbf{Dependency/environment state} can carry hidden history. Caches and local databases must be identically seeded or reset.

\textbf{Model nondeterminism and provider drift} can produce outcome differences unrelated to state persistence. Sampling configuration must be pinned where possible; repeated confirmatory trials are required.

\subsection{Selection and author bias}

\textbf{Private-subject/author bias} is severe for P0. The likely subject is a system the author knows well and may have designed with unusually strong tests, documentation, and repository discipline. That repository may already favour the RaS hypothesis.

\textbf{Historical commit survivor bias} selects work that is known to have reached a successful future state. Dead ends, ambiguous tasks, and failed changes are underrepresented.

\textbf{Task-selection bias} arises if the author chooses tasks with clean repository traces or expected reset success. A frozen candidate window, inclusion/exclusion rules, task hashes, and sampling procedure are required.

\textbf{Sequentiality} must be real. Five unrelated bugs do not test programme continuity, but artificially chaining tasks can favour the theory. Later tasks should depend naturally on earlier accepted code, interface, test, architecture, or state transitions.

\subsection{External validity}

A single private repository, model family, language, architecture, and highly curated engineering environment cannot support general claims. Public unrelated repositories, multiple languages, multiple models, independent task sets, and independent replication are required.

Repository size, task locality, dependency width, documentation quality, test quality, and retrieval quality may interact strongly with reset performance. A result on a disciplined repository may not transfer to large, poorly documented, cross-service systems.

\subsection{Statistical conclusion validity}

Approximately five tasks and one run per condition cannot establish superiority or non-inferiority. P0 is a methodology pilot/initial case study. It can reveal broken methodology, leakage, unmeasurable reconstruction, or catastrophic continuity failure; at best it can produce supportive pilot evidence.

Later inference requires repeated runs, a declared task population, a justified non-inferiority/equivalence margin, dependence-aware uncertainty intervals, missing-data rules, stopping rules, and multiplicity treatment.

The accepted Subject-B evidence illustrates why the result scale matters. P1 observed equal non-zero performance (18/30 in each condition), whereas P2 observed equal zero performance (0/39 in each condition). P2 therefore has a floor effect: its 39 agreements and zero disagreements do not show that either condition successfully preserved behaviour, and P1/P2 correctness values must not be pooled.

\subsection{Prior empirical evidence adverse to a strong thesis}

Handoff Debt reports substantial rediscovery overhead for repository-only successor agents on interrupted tasks \citep{kc2026handoff}. That experiment is not the same as post-acceptance RaS, but it raises the prior probability that repository-only resumption can be expensive. A P0 result in which reconstruction dominates tokens/events/time is therefore not surprising and must count as evidence against the economic thesis.

\subsection{Central falsification conditions}

RaS is weakened if reset reduces verified task success beyond a preregistered acceptable margin; complete-sequence success collapses with depth; reconstruction dominates resource use; persistent history consistently yields better outcomes; success depends on unusually tailored semantic documentation; or advantages disappear on larger, non-local, unrelated repositories. These conditions are expanded in \texttt{paper/falsification-criteria.md}.
