\section{Approximate Repository Sufficiency}
\label{sec:sufficiency}

The central continuity hypothesis can be expressed in terms of future action. Let $H_t$ be complete historical engineering interaction up to time $t$, $R_t$ durable repository state, $U$ a new task, and $A_{t+1}$ a useful or correct next engineering action.

An ideally sufficient repository would satisfy:
\begin{equation}
P(A_{t+1}\mid H_t,U)
=
P(A_{t+1}\mid R_t,U).
\label{eq:ideal-suff}
\end{equation}
Exact equality is unrealistic. Historical interaction can contain arbitrary information that was never externalised, and the space of useful engineering actions is not directly enumerable.

A conceptual approximate definition is:
\begin{equation}
D_{\mathrm{KL}}\left(
P(A\mid H_t,U)
\;\|\;
P(A\mid R_t,U)
\right)
\le \epsilon.
\label{eq:epsilon}
\end{equation}

Equation~\ref{eq:epsilon} is not included merely to make the paper look formal. It is useful because it states the intended notion of sufficiency precisely: removing historical interaction should not materially change the distribution over useful next actions, within some tolerated divergence. It also makes clear that repository sufficiency is task-conditional. A repository can be sufficient for one task and insufficient for another.

Literal KL divergence is unlikely to be directly observable in deployed agents. The action space is open-ended, model probabilities over complete engineering trajectories may be inaccessible, and different surface actions can be functionally equivalent. The equation is therefore a conceptual definition rather than the proposed experimental statistic.

The experiment operationalises sufficiency through observable proxies:
\begin{itemize}
    \item engineering task success;
    \item hidden behavioural verification;
    \item state-reconstruction accuracy;
    \item regression rate;
    \item successful resumption after forced reset;
    \item reconstruction cost.
\end{itemize}

These proxies capture different failure modes. A fresh reasoner can identify the correct architecture but fail implementation. It can implement a locally correct change while violating a hidden invariant. It can eventually succeed only after reading most of a large repository, producing poor economics. Conversely, it can produce an incomplete verbal reconstruction yet succeed because executable tests constrain the relevant behaviour.

Repository sufficiency is therefore not synonymous with repository completeness. A repository need not preserve every past thought. It must preserve enough decision-relevant state, or enable sufficiently reliable reconstruction from its artefacts, for future correct action.

Semantic-state ablation provides a causal probe. Condition C removes selected state carriers according to a preregistered manifest while preserving the task and executable baseline. Candidate carriers include architecture decisions, concise state documents, agent instruction files, semantic product documentation, selected history, or other non-source artefacts. If correct continuation falls after an artefact class is removed, that suggests the class carried useful continuity for the tested tasks.

Ablation is complicated by redundancy. A decision may appear in source structure, a test, a schema, an ADR, and a commit message. Removing one representation may leave the information recoverable elsewhere. Conversely, deleting too many artefacts can change the engineering task rather than merely the continuity available to solve it. Ablation therefore requires an information-leakage audit as well as a file manifest.

The strong RaS hypothesis is not that $R_t$ always replaces $H_t$. It is that for an important class of software-engineering work, the marginal value of full historical conversational state can be made small enough that durable repository state becomes the primary continuity mechanism.
