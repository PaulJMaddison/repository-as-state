\section{Approximate Repository Sufficiency}
\label{sec:sufficiency}

The central continuity question can be stated more precisely in terms of future action. Let $H_t$ be the complete historical engineering interaction up to time $t$, $R_t$ the durable repository state, $U$ the next task, and $A_{t+1}$ a useful next engineering action. An ideal repository would preserve all history relevant to action selection:
\begin{equation}
P(A_{t+1}\mid H_t,U)
=
P(A_{t+1}\mid R_t,U).
\label{eq:ideal-suff}
\end{equation}

Exact equality in Equation~\ref{eq:ideal-suff} is unrealistic. Historical conversation may contain arbitrary information not represented in the repository, and the space of useful engineering actions is not directly enumerable. We therefore introduce \emph{$\epsilon$-repository sufficiency} as a conceptual approximation:
\begin{equation}
D_{\mathrm{KL}}\left(
P(A\mid H_t,U)
\;\|\;
P(A\mid R_t,U)
\right)
\leq \epsilon.
\label{eq:epsilon}
\end{equation}

Equation~\ref{eq:epsilon} is a theoretical device, not a proposed directly measurable statistic. In realistic agent systems, the underlying action distributions may be inaccessible, model versions may change, and task success depends on execution and verification as well as action selection.

RaS therefore operationalises repository sufficiency through observable proxies:
\begin{itemize}
    \item correct engineering continuation under independent acceptance criteria;
    \item hidden behavioural verification;
    \item successful resumption after forced reset;
    \item reconstruction accuracy for task-relevant constraints;
    \item regression rate;
    \item reconstruction cost;
    \item human intervention required to recover missing state.
\end{itemize}

These measures capture different failure modes. A fresh agent may reconstruct the correct architecture but fail execution. It may complete a task while violating an undocumented invariant. It may eventually succeed but require reading most of the repository, making the continuity mechanism economically unattractive. A single success metric would hide these distinctions.

\subsection{Repository Resumability Index}

We propose the Repository Resumability Index (RRI):
\begin{equation}
\mathrm{RRI}
=
\frac{
\text{successful correct continuations after complete agent-state reset}
}{
\text{eligible forced resets}
}.
\end{equation}
Equivalently, RRI estimates
\begin{equation}
P(\text{correct continuation}\mid\text{complete conversational-state reset})
\end{equation}
under a specified protocol.

RRI is not an established standard. Its value depends critically on the success definition and eligibility rules. A continuation should not count as correct merely because code was produced or compiled. The preregistered acceptance criterion should include hidden behavioural checks or another independent specification not available for solution leakage.

RRI should also be measured by sequential depth. Let $\mathrm{RRI}_d$ denote success following a reset at depth $d$. A high aggregate RRI can hide degradation after many transitions. Depth-specific reporting can reveal whether repository continuity erodes as decisions accumulate.

\subsection{Semantic-state ablation}

A high RRI would still leave a causal question: what part of the repository carried continuity? Condition C removes selected semantic artefacts according to a preregistered manifest while retaining source, tests, and build rules. Candidate ablations include architecture decisions, concise state documents, semantic product specifications, or selected history.

If performance falls when a class of artefact is removed, that provides evidence that the artefact carries decision-relevant state. If performance is unchanged, the artefact may be redundant for the tested tasks, or its information may be recoverable elsewhere.

The ablation must avoid future-history leakage. Removing a design document while retaining later tests or comments that explicitly encode the same answer may fail to remove the relevant information. Repository sufficiency is therefore a property of the complete information topology, not individual file types in isolation.
