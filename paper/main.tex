\begin{abstract}
Long-horizon software-engineering agents are commonly discussed as persistent processes whose conversational history, working memory, or model-side state carries continuity across tasks. This paper investigates a different systems architecture: \emph{Repository-as-State} (RaS), in which the durable software repository is treated as the primary carrier of engineering continuity and high-capability reasoning is invoked transactionally. A reasoning process receives durable repository state and a current task, reconstructs a bounded task-relevant subset of state, proposes a state transition, and may then disappear after implementation and deterministic validation persist the result. We formalise the continuity question, introduce an approximate repository-sufficiency concept, propose the Repository Resumability Index (RRI), derive provider-neutral context-scaling and tiered-execution cost models, and define a forced-state-reset evaluation that deliberately destroys conversational continuity between sequential engineering stages. A central falsification condition is reconstruction cost: RaS is weakened if repository rediscovery grows enough to erase any benefit from avoiding persistent historical state. We also examine tests as executable semantic memory, least-privilege implications of separating reasoning from execution, and repository infrastructure precedent for durable state with replaceable serving compute. Controlled empirical results are not yet available; the present paper is a theoretical and methodological baseline for preregistered pilot and replication studies.
\end{abstract}
