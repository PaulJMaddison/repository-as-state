# Experiment plan

## P0 — Forced-State-Reset Pilot

Purpose: validate the intervention, task sequencing, hidden verifier, telemetry and public/private evidence pipeline.

Current status: **not executed**.

Required before execution:
1. select the private task corpus without copying proprietary source into this repository;
2. pin the subject revision for every task boundary;
3. define task success and hidden behavioural verification;
4. pre-register reset enforcement and allowed inputs;
5. finalise reconstruction-cost classification;
6. define telemetry completeness rules;
7. freeze exclusion and human-intervention rules;
8. commit the preregistration before observing outcomes.

## P1 — Controlled continuity replication

Compare persistent monolithic control with forced-reset RaS across multiple task sequences and preferably public repositories. Estimate RRI by depth and outcome-normalised reconstruction cost.

## P2 — Semantic-state ablation

Remove preregistered repository artefact classes to estimate which forms of source-adjacent semantic state carry continuity. Guard against redundant information and future-history leakage.

## P3 — Tiered execution

Compare monolithic high-capability execution with high-capability reasoning plus constrained lower-cost or stateful workers. Include retry, escalation and orchestration costs.

## P4 — Scaling and cross-model replication

Vary repository size, dependency width, model family, tool support and documentation quality. Test the bounded-reconstruction assumption directly.

## Decision gates

A strong RaS claim should not proceed if forced-reset task quality falls materially, hidden verification is not independent, reset enforcement cannot be demonstrated, or reconstruction telemetry is too incomplete to evaluate the main falsifier.

A state-economics claim should not proceed unless outcome-normalised measured cost proxies are lower after reconstruction and retry costs are included.
